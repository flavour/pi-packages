## The 15 assets to take (highest value first)

1. **PERMIT** `combine()`: two-sided bands + `q_critical` blocks alone, `q_risk` blocks only when authorization is weak.
   Answers SPEC §7 candidate (c) with a measured basis.
2. **PERMIT** question split *hazard* vs *user authorization*, and the 100-refusals-of-125 evidence
   for why one merged probability fails.
3. **AUTO** `mode: required|hazard` + `severity: soft|hazard` + `clearedByIntent` — "can consent clear this?"
   as a first-class axis.
4. **GUARD** 1-10 strictness scale → `{reviewProbability, highRiskProbability, severityReview}` table
   - per-tool boost.
     Answers §17-1: ship a scale, calibrate the probabilities.
5. **PERMIT** `unbreakable`: credential/protected-path calls are excluded from the repeat layer, the
   tripped breaker and grants — "get refused twice, then read the key" must not work.
6. **GUARD** `fitState` degradation ladder + `pendingTool.truncated` + `truncateMiddle` +
   `stableStringify` (stable key order — required for our prefix cache to pay off).
7. **PERMIT** `splitChain` + taint + `effectiveCommandIndex` (sudo/env/wrappers) +
   `resolveLiteralAssignments` (`T=…; rm -rf $T`).
8. **PERMIT** `test/replay.ts`: rebuild a corpus from session transcripts (`jq … | @json`), keep only
   what reaches the model layer, one favourable intent for all, `--dry` for the local pass.
9. **GATE** shared browser approval queue + `HumanDecision.unavailable` + terminal fallback → our
   §8.2 RPC answer.
10. **GATE** `NO_RETRY_NOTICE` ("rewording, splitting, scripts, or other tools") and the argument for
    withholding rationales from the agent.
11. **GUARD** `score` ordinal question (4 written anchors) for severity — easier to measure on a 3B
    model than a calibrated `p`.
12. **PERMS** reviewer lineage: fingerprint (model+config+prompt+trust) + evidence-prefix check + token budget → delta turns.
    Maps directly onto our measured LCP prefix-cache behaviour.
13. **PERMS** MCP argument projection (`GENERIC_ARGUMENT_KEYS`, scalars only) + `toolBaseName`.
14. **AUTO** conditional question asking (`requiresPolicy` / `requiresProtectedTarget` /
    `requiresReason` / `requiresFlagged`) — keeps the set affordable at ~130 ms/question on `d1-3B`.
15. **GUARD** key-name redaction over arbitrary tool input; **PERMIT** verify-the-key-by-asking-a-real-question;
    **PERMIT** `shadow` window + `kind:"window"` log records.

## What no project provides (still ours to design)

- Any **local/decision-endpoint** coupling: all five target hosted TypeSafe (`jev-latest`, `TYPESAFE_API_KEY`, `@typesafe-ai/sdk`).
  Our plain-HTTP `jetson` client, `max_tokens: 1`, `temperature: 0`, and the model/build/`--parallel`/`n_ctx` startup assertion are new work.
- **State budget in tokens.**
  Every project caps by characters (120 000 or 12 000).
  Our measured budget is ~1 500 tokens/slot with a per-group state re-read — no prior art here.
- **Prefix-cache-aware state construction.**
  PERMS gets closest (append-only lineage) but nothing measures server-side prompt reuse; our Phase 1 result is the only evidence.
- **Question-count ceiling from server parallelism.**
  Our finding (4 questions per request at `--parallel 4`, a 5th starts a second group and pays another state read) has no analogue.
- **`user_bash`, background tools, MCP annotations, nested `executeTool`.**
  Zero coverage in all five.
- **A decision corpus with expected outcomes.**
  PERMIT's replay has no expectations; AUTO's fixtures are 13-19 hand-written.
  Our §14 corpus is net-new work.
